# Phase 2 implementation review

**Historical verdict: Phase 2 failed six additional checks.** The findings below now have fixes and permanent regressions. [Current progress](../../PROGRESS.md) records their verification and the Phase 3 implementation. The user selected direct code verification. This report preserves that audit and does not claim an EGM Goldfish round.

## Verified paths

- The full suite passed **85 tests**, with zero skips and five PyMuPDF/SWIG dependency warnings. The run exercised real PaddleOCR, the pinned CPU EmbeddingGemma 2 and MiniLM models, a SmolLM2 loopback chat server, PostgreSQL migrations, Qdrant, Redis and Celery. Ruff, the dependency lock check and Git whitespace checks passed.
- The synthetic development evaluation again ranked expected evidence first on 50 of 50 questions. All five existing negative questions abstained. Development and held-out fixture hashes matched the earlier [evaluation artifact](phase2-development-2026-11-08.json).
- The running application containers and database were left in place. Probes used synthetic PDFs, a disposable PostgreSQL database, unique Qdrant collections and a local chat fixture. External HTTPS provider integration, the held-out evaluation and resource use on the proposed 2-vCPU host remain unverified.
- The graph index predates the implementation. Coverage reported the inspected paths as untracked, so findings rely on source and executable probes.

## Confirmed findings

| ID | Priority | Reproduction and observed result | Expected behavior |

| P2-F1 | Blocker | Pause `HTTPConnection.request` after the pre-send callback has returned and before the first HTTP write. The workspace lock in the callback ends before the transport writes. [Transport](../../backend/documind/chat.py#L136), [query guard](../../backend/documind/queries.py#L246) | Deletion and outbound request admission must have an ordering that prevents a first write after deletion commits. The probe did not send traffic to it. [Address predicate](../../backend/documind/chat.py#L56), [RFC 3879](https://www.rfc-editor.org/rfc/rfc3879.html) | Reject site-local destinations in both literal URL and DNS-result validation. |
| P2-F3 | Major | Upload and publish a PDF with `Invoice number: INV-100`, `Invoice number: INV-200` and `Grand total: USD 42.00`. The unqualified grand-total question returns supported. [Version selection](../../backend/documind/publications.py#L64), [deletion cleanup](../../backend/documind/repository.py#L874) | Rebuild from surviving eligible versions, preserving A's last published complete extraction while its new preview awaits review. |

[Readiness](../../backend/documind/api.py#L169), [retrieval check](../../backend/documind/publications.py#L378) | Report search unavailable when the active artifacts are mismatched. |

[Runbook](../LOCAL_DEVELOPMENT.md#phase-2-hybrid-search-and-baseline-qa), [question grammar](../../backend/documind/evidence.py#L18) | The walkthrough should use a supported query, or the explicit grammar should accept the walkthrough question. |

The boundary probes ran with `DOCUMIND_TEST_RETRIEVAL=1 uv run --no-sync python -m pytest -q --tb=short .data/phase2-audit-probes/test_phase2_boundaries.py`. F3 accounts for two failing cases. F1 used the loopback fixture and synthetic evidence only. The source, existing tests and runtime settings were unchanged during the review.

## Resolution

The fixes and permanent regressions are in [test_phase2.py](../../backend/tests/test_phase2.py). F1 holds authorization through the bounded outbound request write and tests both deletion orderings. F2 tests literal and DNS site-local IPv6. F3 preserves unparsed competing fields as uncertainty and rejects multiple invoice identities. F4 adds the last-published version pointer and exercises migration backfill plus replacement. F5 shares artifact validation between retrieval and readiness. F6 accepts the walkthrough's invoice-grand-total question. [ADR-026](../../DECISIONS.md#adr-026-local-workspace-ui-and-replayable-query-events) records the choices.
