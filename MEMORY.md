## Product and boundaries

- DocuMind is a business-document intelligence platform. The original [Self-RAG PDF](reference/original_self_rag_spec.pdf) supplies the research baseline; its GATE/UPSC corpus, Streamlit UI, estimates and example resume metrics are not current product requirements or measured results. [Source deviations](docs/CHANGES_FROM_PDF.md) are authoritative.
- The implemented local slice covers PDF ingestion, optional English CPU OCR, ruled tables, immutable human review, hybrid retrieval and evidence-checked baseline QA. The full architecture is a staged design, not a list of deployed capabilities. See PROGRESS before choosing work.
- DocuMind is local-only under ADR-042. The UI, API, workers and stores stay on the user's device. The fine-tuned model independently uses the device or private Kaggle, and generation uses the device, private Kaggle or a selected endpoint/key. Keep the configured workspace and private Bearer token with published ports on loopback.
- A source quote must resolve to stored raw text and immutable document/version/page/element anchors. PDF pages are 1-based; boxes use normalized top-left coordinates on the rotated rendered page. Native confidence is null, not certainty.
- `Decimal`/rules must own arithmetic. Document-specific queries retrieve authorized evidence; documents never supply instructions or tool permissions.
- Qdrant loopback binding is insufficient protection. Compose requires the private client/server key and disables CORS. Upgrade existing configuration using `scripts/init_local.py --secure-qdrant`; preserve the volume and restart host clients. [Runbook](docs/LOCAL_DEVELOPMENT.md#existing-qdrant-installations).
- Physical deletion needs the same document lock as page writes, with the lease checked inside that lock. Final SQL fencing alone cannot prevent a late file write. `db.artifact_lock` acquires without waiting; contention follows the existing `PUBLICATION_BUSY` retry policy. [Race regression](backend/tests/test_ingestion.py).
- Readiness must compare actual Alembic revisions with application heads. HTTP repository admission rejects mismatches before touching new columns. Health is only process liveness. Never migrate a populated database automatically to make checks pass.
- A reflection HTTP timeout does not cancel decoding. Persist each step deadline for exact replay, cancel that exact step on transport failure and retain the query-wide budget separately. The guardian must clean its process group even after normal parent exit. [Runtime regressions](backend/tests/test_reflection_runtime.py), [process regressions](backend/tests/test_runtime_lifetime.py).
- Connection receipt loss needs the same immutable body/key on retry, including PATCH's original expected version. Keep credentials only in transient memory. A rejection during recovery does not prove the original write failed. Reload discards that recovery state; inspect saved connections before creating again. [Browser regression](frontend/tests/workspace.spec.ts).

## Model and inference commitments

- ADR-020 selects text-only `google/embeddinggemma-2`, normalized 768-dimensional vectors. The retained reranker is `cross-encoder/ms-marco-MiniLM-L6-v2`; ADR-031 pins `Qwen/Qwen3-4B-Instruct-2507` for controlled generation. The real Phase 2 text embedder and reranker are pinned in search_models.py. Quality evidence is limited to the labeled fixtures in PROGRESS.md.
- [RETRIEVAL.md](docs/RETRIEVAL.md) owns `hybrid-v3`, tokenizers, prompts and budgets. Its 240/64 chunks are measured with the reranker tokenizer; a larger Gemma context does not remove the reranker's pair limit. Model/prompt changes require isolated encoding/index identities.
- [INFERENCE.md](docs/INFERENCE.md) defines the two independent roles. Split reflection sends the selected generator's exact candidate to the fine-tuned model for labels. The trained role still needs its base, adapter and tokenizer. Save both identities and the split/integrated strategy. Native preview and comparisons remain independent.
- A trained release is fixed until deliberately retrained/versioned. Uploads and queries update evidence/context, not weights. Save the base revision, adapter, tokenizer/token map, trained token rows and protocol/runtime manifest together. The selected bundle has explicitly delegated local experimental operator validation; a representative human/research release remains open.
- Connection/mode switches are explicit new runs. No silent provider fallback or data forwarding. The local Kaggle bridge uses configured operator credentials, exact-session lifecycle and inference-only loopback routes. Its command and remote model behavior need separate verification.
- Split reflection journals generator intent before dispatch and saves the exact candidate with the trained critic step. Replay uses confirmed text and model results. Optional `candidate_text` is omitted when absent to preserve older wire hashes. CPU/MPS and NF4 CUDA expose distinct inference profiles and require their own quality checks.
- Local model capacity depends on the user's device and selected precision. CPU/MPS inference, OCR and retrieval share device resources. Measure actual memory and latency for the model profile and preserve a private Kaggle option for machines that cannot fit the base plus adapter.
- Keep target-model quality runs separate from a full test suite or another local model load on a 16 GB device. MPS cold requests exceeded the generator deadline under memory pressure; an isolated Qwen FP16 calibration completed in 2.05 seconds. Calibrate after retrieval weights load, outside user-query deadlines. A ready health endpoint alone does not establish first-request latency.
- Run the scripted-runtime test suite with default inference settings before switching the test installation to a pinned live profile. A live profile pin can reject the fixtures. Check the selected model through the full PDF query after startup. On the 16 GB Mac, trained FP16 MPS reached readiness on retry but timed out in candidate generation. Treat the earlier FP16 MPS generator result as evidence for that role only. [Local acceptance](docs/validation/local-release-2026-11-15.json).
- Verify cached model bytes against the pinned registry revision's LFS SHA-256 and size. Cache blob names can use a different content address. An offline load establishes cached setup, while fresh provisioning requires a download check. [Local acceptance](docs/validation/local-release-2026-11-15.json).
- A validation-selected immutable bundle can legitimately omit conditional test scores. Run `evaluate_reflection_v3.py --conditional` without training and bind its complete test scores inside a fresh generated-evaluation artifact. The review gate rejects wrong bindings, missing rows and replacement of bundled test results. Never repack or alter weights just to add metrics (ADR-043).
- Phase 8 pairs baseline and trained reflection on a single pinned NF4 Qwen profile per shard. The 200-case post-training synthetic set must stay separate from the 60-case pre-training test split. Compare verified output separately from raw candidates and preserve source page/span anchors. The support ablation changes acceptance and scoring alone, so exact-prefix reuse is valid for quality and makes latency incomparable. [Evaluation protocol](docs/EVALUATION.md#10-phase-8-controlled-comparison).
- Physical trained-row tensor counts depend on tied embeddings. `reflection_runtime.load` expects one delta tensor for a tied input/output embedding and two otherwise; each contains all 15 rows. Do not treat one shared tensor as missing output supervision.
- Gold counterfactual and positive episodes can share passage text while having different source IDs and answer prefixes. Do not equate conditional label probabilities with greedy outputs by episode number alone. Protocol-equivalence scoring must use the exact serialized context and actual generated prefix; the target GPU wire check covers all reflection families.
- Delegated agent review needs explicit authorization and its own identity (ADR-044). The v4 operator verdicts are agent evidence; they are not the user's v3 human review or human-verified training/benchmark labels.

## Lessons that must survive implementation changes

| Discovery | Consequence / evidence |
|---|---|
| Generated unique-constraint names collided when based only on the first column | Schema names include all constrained columns; verify migrations against real PostgreSQL. |
| The demo worker could consume integration jobs sharing its queue | Isolate database, object root **and** Celery queue/key prefix; see [test fixtures](backend/tests/conftest.py). |
| Deletion invalidates the active ingestion lease before promotion | A stale worker may stop with `LEASE_LOST`; API reads must still fail closed. |
| An older extraction can finish after a newer preview | Guard preview-pointer promotion; preserve the newest applicable preview. See `test_old_completion_cannot_replace_newer_preview`. |
| Failed reprocessing must not erase the last usable source | Keep immutable versions and a separate preview pointer; tested by `test_reprocessing_failure_preserves_previous_preview`. |
| Polling DB jobs can flood the broker before a worker claims them | Reserve sends atomically in PostgreSQL for 60 seconds. A consumer can claim during the reservation, and the processing lease still fences duplicates. See [ADR-046](DECISIONS.md#adr-046-separate-artifact-admission-send-reservations-and-worker-leases). |
| Checking visibility once before reading text leaves a deletion race | Recheck source visibility before returning content; the 2026-11-08 review reproduced a page response after deletion committed before its SELECT. Both routes are now covered by `test_deletion_during_text_read_revokes_response`. |
| A heartbeat before staging leaves a physical deletion race | Coordinate the file write and cleanup as well as the final DB fence. The November 16 audit recreated a PNG after a successful cleanup receipt. [Open finding](docs/validation/deep-audit-2026-11-16.md). |
| Document and element rows carry different cursor identities | Encode the same primary key used by the query's ordering/filter, and test full pagination, not just the first page. |
| Calling `logger.info` does not establish observable request logging | Test the effective logger level/handler under actual Uvicorn startup; its default configuration suppressed DocuMind request records in the review. |
| Valid citation identity is not substantive support | The evidence-v1 gate independently validates claims; ranking scores and critic labels cannot certify arbitrary prose. |

Test names above are in [test_ingestion.py](backend/tests/test_ingestion.py). Preserve meaningful regression coverage when those implementations change; remove or revise a lesson only when its underlying constraint changes.

The three Phase 0/1A review defects are fixed with regressions in test_review_regressions.py. PROGRESS.md owns current validation.

## Phase 1B operating constraints

- ADR-024 selects PaddleOCR 3.7.0 / PaddlePaddle 3.3.1 CPU, PP-OCRv5 mobile detector and English recognizer. Provision once with scripts/setup_ocr.py; inference requires verified local artifacts and never substitutes native text for requested but unavailable OCR. Config and page provenance retain model revisions/file hashes. OCR is disabled in the default native-only Compose deployment.
- Native ruled tables use PyMuPDF; complete raster grids use OpenCV plus actual OCR. Preserve empty cells, spans, parent IDs, coordinates and header uncertainty. Do not claim general layout, automatic cross-page linking or calibrated confidence.
- All OCR/table extraction requires human review. The review route confirms all pages and optionally corrects existing text/header flags; it creates a new immutable version through the durable job path. It cannot add missing cells, repair geometry or make empty scans successful. Earlier source versions remain available until deletion.
- Table deduplication must work at word/span boundaries: filtering whole native blocks lost adjacent text. The one-sided regression passes, but a subsequent audit reproduced two-sided text loss after remaining words were grouped into a box and filtered again. Merged-cell spans/row delimiters have their own passing regressions; do not generalize them to all table layouts.
- Preserve existing idempotency payloads across upgrades; adding a null field changes request fingerprints. Use one clock consistently for writing and selecting local job deadlines; mixing host writes with PostgreSQL time caused a reproduced lease-recovery failure.
- PostgreSQL CHECK accepts SQL NULL: JSON structures require object/type guards in addition to required-key and numeric comparisons. Migrations 0002/0003 add table provenance and reject invalid/null/array coordinates.

## Verified Phase 1B and Phase 2 lessons

- The six Phase 1B audit cases now have regressions in `backend/tests/test_extraction.py`. Preserve source order during review, atomically select completed previews, resolve durable upload replays before OCR checks, retain outside-table fragments and assign each raster OCR line once.
- Phase 2 uses pinned local embedding and reranker weights with explicit tokenization. SentenceTransformers initialized the multimodal processor despite disabled encoder towers. The tested Transformers loader skips those towers and applies the checkpoint's masked mean including its prompt.
- Recount chunk overlap on the exact shared raw substring. A WordPiece continuation can re-encode to more tokens after splitting. The real MiniLM regression covers a 64-token boundary that previously re-encoded to 65.
- PostgreSQL is the publication authority. The active pointer advances only when both artifacts match and the frozen parent and sources are still valid. Retired publications may serve pinned queries. Source deletion revokes affected snapshots and their runs before physical cleanup.
- The query worker records provider dispatch intent before sending evidence. If a lease expires after that point, the run fails without repeating a potentially billed completion. Treat provider output as untrusted and retain the deterministic field answer when candidate text differs.
- Test revocation before the first outbound write as well as during inference. A pre-send DB check that releases its lock before the write leaves a race even when result reads fail closed. The Phase 2 audit also reproduced Python classifying a site-local IPv6 address as global, so endpoint tests need explicit site-local coverage.
- Phase 2 uses one local principal per configured workspace. The operator sets a private encryption key and can allow one exact loopback chat URL. Public HTTPS requests resolve and pin a vetted address while verifying TLS against the original hostname.
- The Phase 2 fixes hold the workspace lock through the bounded request write, explicitly reject site-local IPv6, retain uncertain labeled values and enforce a unique source invoice identity. Migration 0005 preserves the last published source for surviving documents after revocation of a shared snapshot.
- Next.js forwards to the loopback API with a server-held token. The workspace renders authorized PNG pages, resolves citation geometry from the backend and pins the selected connection version. A citation drilldown must expose `citation_id` consistently with the answer projection so the viewer opens the cited page.
- SSE reads the durable event ledger. Terminal frames link to the authorized result route, and midstream revocation closes the subscription with a transient error. Browser reconnect deduplication and a real killed/restarted Celery query are covered. The browser fixture uses a synthetic completion endpoint, with real model inference tested separately.
- A successful result read does not establish that the browser received its terminal SSE frame. Test reconnect both before and after the run finishes. Bind any human review checkbox to the exact extraction version, because a refreshed preview can change while the form stays mounted. [Phase 3 audit](docs/validation/phase3-review-2026-11-09.md).
- Query receipt loss must preserve the original body/key, source scope and destination/config version. Retry recovers the same run; a separate run requires explicit user action. Clear cached answers/highlights on `QUERY_RECHECK_REQUIRED` as well as revocation. The real browser test drops an accepted response and checks identical request/run identities.

## Phase 3 and Phase 4 implementation lessons

- Retry the same upload selection with its original key until receipt. Chromium can lose the response after the backend accepts the upload. When a source is revoked, clear cached answers, comparison findings, download links and pinned highlights on workspace refresh.
- An investigation pins extraction versions at creation. Later review can change the preview without changing the investigation. Read the typed records from PostgreSQL, recheck each supported field against its exact raw label span and recompute the Decimal difference before serving results or CSV bytes.
- Two `numeric(20,6)` operands of opposite signs can need a 15-digit integer difference. Store the difference as `numeric(21,6)` and preserve up to six fractional digits. A comparison can run with indexing and generation disabled.
- A reviewed table can still contain competing comparison fields. Paragraph-only parsing must abstain when an explicit comparison label appears in a table cell. Findings and CSVs created before that guard need read-side revalidation.
- A ready report URL is a claim that the artifact can be served. Validate the current finding before creating or replaying a report and verify the stored bytes before returning ready metadata.
- Upload quota checks belong inside the workspace lock after idempotent replay and before object storage. Count pending cleanup until deletion finishes. The browser can delete a PDF to recover capacity. [ADR-045](DECISIONS.md#adr-045-bound-workspace-uploads-and-recover-comparison-submissions).
- A comparison may be accepted before the browser loses its receipt. Reuse its original selected set and key. Refresh checks the open detail and source link even if investigation history still lists it. Tests with two populated workspaces should check foreign IDs under both the foreign and authorized prefixes.
- Cover both comparison failure windows. Keep the request key until the create receipt arrives, then keep its investigation ID across detail-read failures. Use the known ID for recovery. [Regression](frontend/tests/workspace.spec.ts).
- Size limits govern new uploads. Accepted originals keep their stored digest and a stable read bound. Legacy rows with a digest and no size require verification before that size can be used as a bound. Legacy PNGs have structural checks but lack a historical digest. [Storage implementation](backend/documind/storage.py).
- Deletion first revokes visibility, then releases quota on successful cleanup. Dependency interruptions use the existing job retry budget. Exhausted jobs are discoverable after a browser reload and can be retried with the same cleanup job ID. [Recovery contract](docs/INGESTION.md).

## Phase 5 research implementation

- Phase 8 v2 reports require every declared arm, runtime evidence for paired runs and a trusted source checkout. The three broader November 15 GPU shards recorded different evaluator hashes. Keep corrected raw scores per shard and scope new retrieval metrics to each case. [Evaluation contract](docs/EVALUATION.md#10-phase-8-controlled-comparison).
- Freeze the synthetic manifest before training and check it independently at trainer startup. Resolve exact anchored text before serialization. Mask all context, role headers and padding. Keep conditional critic-label scores and raw model IDs separate.
- PEFT saves selected input and output token rows with the adapter. Check gradient, change and reload identity on every row. CPU checkpoint defaults can select BF16 and make Mac training slow. Set FP32 explicitly for the CPU smoke. On CUDA, the PEFT training preparation casts unquantized embeddings and the head to FP32. Apply the same preparation during reload with gradient checkpointing disabled so token rows and probe logits match.
- Gated model access is separate from Kaggle account access. The configured account could authenticate to Kaggle, while both registry probes returned 403 for the target Llama tokenizer. ADR-031 superseded the gated Llama target with open Qwen.
- Valid token grammar and exact anchors do not prove an annotation trajectory. Check the provenance of each committed segment and permit evidence reuse only within the retrieved scope. Score frozen test rows explicitly and bind manual review to the checkpoint manifest and hashed artifacts.
- Reject identical segment-and-evidence commits in training trajectories. The runtime stops such cycles before adding duplicate answer segments.
- Successful QLoRA reload and registered reflection IDs establish compatibility. The first pinned Qwen NF4 run reloaded all 15 rows and still missed every required initial retrieval. Report raw decisions separately from policy overrides and score candidate generation separately from gold-prefix critic labels. [Measured run](docs/validation/phase6-qwen-2026-11-09.json).
- The selected lower-rate Qwen run scored 24/24 held-out support labels with gold prefixes, while greedy candidates could emit the wrong date or currency and still claim full support. Include generated answer and support checks before human release review. The holdout was scored for both runs. [Measured runs](docs/validation/phase6-qwen-2026-11-09.json).
- Expanded synthetic evidence IDs reveal fixture variants and differ from runtime chunk UUIDs. Treat the current corpus as a diagnostic. Use opaque IDs in new data revisions and preserve the original frozen splits and result records.
- The v2 expanded corpus pairs the exact record's answer with a different visible value in conflict episodes. The previous training loss supervised those incorrect answer words along with negative critic labels. This motivated the masked loss in ADR-034. [Corpus](backend/documind/reflection_corpus.py).
- `training_pair` now masks No/Partially-supported ordinary answer loss while retaining critic labels and visible candidate tokens. The inference serializer is unchanged. Synthetic-v3 uses opaque UUIDs and paired changed-value records, with a fresh grouped holdout. [ADR-034](DECISIONS.md#adr-034-mask-unsupported-answer-words-and-test-copied-values-with-opaque-evidence).
- The v3 comparison measures generated text in gold evidence contexts. Its eligible cases are supplied-reference repetition. Keep addition and end-to-end retrieval coverage separate from the matched v3 result. [Measured comparison](docs/validation/phase6-adapter-v3-2026-11-09.json).
- The actual selected-model application diagnostic used 32 PDFs and 46 cases: 43 expected outcomes, zero false verified answers and 26 scoped resolvable citations. Twelve invoice paraphrases now use bounded `evidence-v1.3`. Long tail evidence retained its amount but lost the distant invoice ID and was marked irrelevant; both arithmetic probes prematurely emitted Finish. Preserve these failures and use fresh grouped data for improvements. Experimental admission/transport injection never establishes production approval. [Evidence](docs/validation/selected-pdf-workflow-2026-11-09.json).
- CI requires a fresh CPU pilot artifact and train/save/reload/authenticated-runtime verification of all 15 trained rows. A missing required bundle fails rather than skips. This tests runtime integrity separately from selected Qwen quality; remote CI execution must be reported independently.
- A valid 240-reranker-token passage can exceed Qwen's 512-token serialized context plus its 132-token candidate reserve. `reflection_context.py` uses the exact admitted tokenizer/template and explicit contiguous field windows. Keep full source verification, exact offsets and immutable bundle limits. Cache the tokenizer with `scripts/setup_search.py --reflection-tokenizer`; weights remain off the app host. [ADR-035](DECISIONS.md#adr-035-fit-explicit-source-windows-with-the-admitted-generation-tokenizer).
- The named invoice can sit outside a valid field window. A two-span runtime can receive the exact identity label and field from one pinned paragraph, with separate offsets and one citation on the retrieved field. Keep the full-source conflict check. Eligible addition validates a generated candidate against integer arithmetic and preserves the raw model action. [ADR-041](DECISIONS.md#adr-041-preserve-invoice-identity-across-distant-fields-and-validate-eligible-addition).
- Reviewed table cells can still contain competing field values or split labels/values. Shared QA verifier `evidence-v1.3` blocks recognized QA table fields on the resolved document before trusting paragraphs. Stored result/event/citation reads recheck support and return `QUERY_RECHECK_REQUIRED` when affected. [Evidence contract](docs/EVIDENCE.md).
- Human review must inspect actual generated answers, critic labels, finish reasons and outcomes. The packet binds a matching test greedy artifact; omitted diagnostic episodes are explicitly unrun. Runtime consumes the separate recorded-review schema and recomputes bindings/counts. Gold-only submissions and accepted false full support cannot pass. [ADR-036](DECISIONS.md#adr-036-bind-recorded-human-review-to-actual-generated-outputs).
- A recorded conditional label is valid only when the finite probability distribution matches its token family and its deterministic winner. Apply the check to bundled and supplemental scores before deriving review totals. [Review validator](backend/documind/reflection_review.py).
- The formal review minimum counts distinct frozen corpus sample IDs spanning both retrieval policies. Record supplementary application cases separately from `ManualReview.cases` and preserve the reviewer's submitted judgments. Record historical API resolution separately from human PDF inspection. [Review status](PROGRESS.md#selected-adapter-human-review--2026-11-09).

## Phase 6 runtime boundary

- The operator pins the approved manifest and origin. Persist runtime instance identity before work starts. A service restart invalidates old step IDs. The workspace fences each outbound write and result commit against current lease and source access.
- The actual SmolLM2 and Qwen NF4 pilots verify model-backed transport and decoding. They advertise `reflection_pilot`, and application admission checks the exact Qwen base and release digest. Keep scripted app integration and transport parity separate from checkpoint quality.
- Kaggle accepted SDK cancellation for the exact owned serving sessions. The original serving gateway later returned HTTP 404. The pinned CLI has no session-cancel subcommand, and notebook version status is distinct from interactive session cleanup. [Live evidence](docs/validation/phase6k-private-serving-2026-11-09.json).
- Cleanup authorization uses the private creation record, configured owner and exact session/operation binding. Current notebook source/version/privacy or deletion must not strand its old owned session. The operator Stop helper must cancel before gateway observation and cannot require a strict notebook poll first. Start/poll still reject modified templates. [ADR-037](DECISIONS.md#adr-037-cancel-the-recorded-kaggle-session-independently-of-notebook-edits).
- Allocation errors enter cleanup; retain the creation response before validating readiness. An unknown create never auto-reallocates. A supplied recovery receipt needs independent operator confirmation of the exact notebook and is recorded as an attestation. Persist allocation expiry, keep it unchanged on resume, and reconcile it on status after restart. The detached watcher needs its host available; the remote guardian independently bounds installation and the model process group. The live run observed independent cancellation and later gateway revocation, while physical GPU deallocation remains unknown. [ADR-038](DECISIONS.md#adr-038-bound-operator-sessions-and-preserve-creation-receipts-for-recovery).
- The private Jupyter session API returns an exact session ID and an authenticated gateway URL. Its path contains a credential. Keep the entire URL in owner-only local state and out of diagnostics, notebook source and public results. The live prototype reached the model through the gateway's loopback-port proxy. [Evidence](docs/validation/phase6k-private-serving-2026-11-09.json).
- A missing private notebook can return 403. Before creating a unique template, require the configured account to match its owner and an empty owned-notebook listing. Preserve create intent before calling the API. Cancellation acceptance, gateway revocation and GPU deallocation need separate recorded observations. The SDK needs explicit scoped connect/read timeouts.
